01 About

AI transformation is an adoption problem before it is a technology problem.

I work with business leaders on AI transformation. The pattern repeats across finance, operations, and IT. The models are good enough. The hard part is choosing the right work, connecting the tool to the systems and data it needs, and getting the people who own the process to trust the output.

How I work

  • Start with the daily work, not the demo.
  • Pick the first project by frequency and pain, not novelty.
  • Decide who approves what before anything touches a system of record.
  • Measure adoption and cycle time, not activity.
  • Keep people on the decisions that matter.
The work that runs a company crosses apps. It carries state across weeks and quarters. It runs while you sleep. And when it writes to a system of record, someone approves it first.

Things I have built.

Tools and systems from the last two years. Each one links to the code or the post that describes it.

01

wiki-template

Open source, Python

Put source documents in a raw folder. Agents turn them into structured, cited, interlinked pages. Future agents answer from the wiki instead of re-reading the same material every time.

View on GitHub 02

prospect-template

Open source, Python

Prospecting workflows for an AI agent. Set up who you sell to and what you can prove. Scan a named account for public buying signals, skipping anything with an open deal. A signal counts only when the fetched source, verbatim quote, and date pass a script check. The research is automated. Drafts stay unsent until a person sends them.

View on GitHub 03

sales-template

Open source, Python

Call prep, interaction notes, due-task triage, pipeline review, and a weekly forecast for a salesperson working with an AI assistant. The assistant gathers evidence and proposes CRM changes. A person approves each one. Nothing sends email.
